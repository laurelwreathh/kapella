# Kapella

Учебный MVP музыкального сервиса на Next.js, TypeScript и Tailwind CSS. Главная идея — персонализация по обычному поведению слушателя с исключением ситуативного прослушивания. Внешние API и серверная база не требуются. Вход и регистрация работают локально в браузере.

## Запуск

```bash
npm install
npm run dev
```

Открыть http://localhost:3000. Для production-режима:

```bash
npm run build -- --webpack
npm run start
```

## Локальная авторизация

При первом запуске открой `/register`, укажи имя, email, тестовый пароль от 8 до 128 символов и повтор пароля. После регистрации откроется Главная. Для повторного входа используй `/login`. Страница `/profile` показывает аккаунт, дату регистрации и статистику его библиотеки; кнопка «Выйти» завершает сессию и открывает `/login`.

`AuthProvider` предоставляет текущего пользователя, `isAuthenticated`, `login`, `register` и `logout`. После перезагрузки сессия восстанавливается. Header показывает инициалы/имя и ведёт на профиль. Общий `AppShell` допускает к музыкальным экранам после восстановления сессии; без входа перенаправляет на `/login`. `/login` и `/register` доступны без входа, а авторизованного пользователя перенаправляют на `/`.

Модуль `lib/auth.ts` нормализует email, проверяет поля и повторную регистрацию, хранит пользователей в `kapella-auth-users-v1`, а ссылку на текущего пользователя — в `kapella-auth-session-v1`. Открытый пароль не сохраняется: используется PBKDF2-SHA256 (210 000 итераций) с отдельной случайной солью для каждого аккаунта. Данные хеша не передаются через `AuthProvider`, URL или профиль. Тестовый аккаунт автоматически не создаётся.

**Это демонстрационная клиентская авторизация, а не production-защита.** localStorage доступен коду браузера и может быть изменён вручную; для реального сервиса нужны серверная проверка и защищённая сессия. Используй отдельный тестовый пароль. Если хранилище недоступно, вход и регистрация показывают ошибку вместо ложного сообщения об успехе.

Библиотека хранится в `kapella-library-v1:<userId>`, настройки Player — в `kapella-player-v1:<userId>`. Смена аккаунта пересоздаёт общее состояние и останавливает старый Player. Избранное, обычная/гостевая история, плейлисты, подписки, профиль вкуса и настройки относятся к текущему аккаунту. Выход сохраняет личную библиотеку для следующего входа. Изменение сессии в другой вкладке обновляет текущий аккаунт и здесь.

Старые общие ключи `kapella-library-v1` и `kapella-player-v1` сохраняются, но не присваиваются новым аккаунтам автоматически: у прежних данных нет владельца. Новые аккаунты начинают с пустой библиотеки.

## Что работает

- Общий Player: запуск с любой страницы, Play/Pause, прогресс, перемотка, громкость, следующий/предыдущий трек, shuffle, repeat и просмотр очереди. Меню трека позволяет поставить его следующим.
- Поиск по названию, исполнителю, альбому, жанру и фрагменту текста. Вкладки треков, исполнителей, альбомов и пользовательских плейлистов.
- Страницы исполнителей и треков, тексты песен, похожие треки, подписки на исполнителей.
- Библиотека: избранное, обычная история, отдельная гостевая история, создание и удаление плейлистов, добавление и удаление треков.
- «Обновить под мой вкус»: просмотр до четырёх новых рекомендаций и добавление их в плейлист с сохранением выбранных ранее треков.
- Персональные рекомендации на Главной и небольшой профиль вкуса в библиотеке.
- Сохранение библиотеки, подписок и гостевого режима в localStorage. Громкость, shuffle и repeat сохраняются отдельно. Воспроизведение после перезагрузки автоматически не запускается.

## Как устроена персонализация

`lib/taste-profile.ts` строит один `TasteProfile` из обычной истории, избранного, содержимого плейлистов и подписок на исполнителей. Этот профиль используется рекомендациями, библиотекой и секцией «Мой музыкальный вкус» на `/profile`.

История принимается только при одновременных маркерах `mode: "normal"` и `eligibleForRecommendations: true`. Профиль содержит веса жанров и исполнителей, количество запусков каждого трека, недавние треки, избранные жанры/исполнителей и статистику обычного прослушивания. Вес запуска — `2 × свежесть / √числа запусков трека`; интерес по давности имеет период полураспада 14 дней и нижнюю границу 20%. Избранный трек получает вес 4, трек из плейлиста — 2.5, подписка на исполнителя — 3. Один трек в нескольких плейлистах не усиливает предпочтение повторно.

`lib/recommendations.ts` — чистый локальный scoring-алгоритм, а не случайная подборка или внешний AI API. `LibraryProvider.getRecommendations(options)` применяет его к данным текущего пользователя; общая подборка на Главной и обновление плейлистов используют этот же метод.

| Фактор кандидата | Вклад в оценку |
| --- | --- |
| Совпадение жанров | до +6 |
| Соседние жанры | до +1.2 |
| Интерес к исполнителю | до +3 |
| Похожие исполнители из `demo-music.similarIds` | до +1.5 |
| Трек в избранном / плейлисте | +1 / +0.65 |
| Подписка на исполнителя | +0.75 |
| Ещё не прослушанный трек | +0.8 |
| Повторные запуски | −1.5 × log₂(1 + число запусков) |
| Трек в недавней обычной истории | −1.1 |
| Частые недавние показы в прошлых подборках | штраф до −1.8 |

При достаточном числе альтернатив трек с тремя и более запусками исключается. Дополнительный отбор учитывает разнообразие жанров и ограничивает одного исполнителя двумя треками в подборке из шести, если каталог позволяет. Результат содержит трек, итоговую оценку, вклады факторов и причины. Краткая причина показана под треком; «Почему?» раскрывает остальные.

У нового пользователя предлагается непустая подборка с учётом демонстрационной популярности исполнителей и разнообразия жанров. После обычных запусков, сохранения треков, изменения плейлистов или подписок профиль пересчитывается сразу. Состав рекомендаций на Главной закреплён до перезагрузки страницы (F5): запуск трека, лайк и переходы между страницами не переставляют карточки. После перезагрузки новый список строится из сохранённых действий. Подбор при явном обновлении плейлиста использует актуальный профиль сразу.

### Учёт предыдущих рекомендаций

До 20 подборок, показанных на Главной при разных состояниях вкуса, сохраняются в `recommendationHistory` внутри личной библиотеки. Это метаданные показов, а не вторая история прослушивания. Вес прошлого показа уменьшается с периодом полураспада 7 дней; показы старше 28 дней не учитываются.

Стабильный ключ вкуса строится только из обычной истории, избранного, уникальных треков плейлистов и подписок. Он не зависит от гостевых данных, названий плейлистов и ID событий истории, которые нормализуются при загрузке. Список Главной и его ключ фиксируются вместе при загрузке библиотеки; запись показа привязана к этому ключу, даже если профиль уже изменился во время прослушивания. Текущая подборка не штрафует сама себя. Повторный заход на Главную, перезагрузка и гостевые запуски не создают новый показ для того же ключа и не меняют подборку из-за гостевого контекста. Прошлые показы учитываются при следующем изменении вкуса.

Профиль и метаданные показов изолированы через существующий `userId` и `kapella-library-v1:<userId>`. Старые сохранённые библиотеки без `recommendationHistory` поддерживаются и получают пустой список показов.

## Гостевой режим

Переключатель постоянно доступен над элементами Player. Режим определяет контекст **новых запусков**; включение режима не перезапускает текущую музыку и не меняет старые записи.

Гостевые события записываются в `guestHistory` с `eligibleForRecommendations: false`. Входом профиля они не являются. Пауза и продолжение не создают повторного события. Новый трек, автопереход и повтор трека создают событие в соответствующем режиме.

Избранное и добавление в плейлист остаются явным выбором пользователя и учитываются в профиле в любом режиме. Это отличается от пассивного гостевого прослушивания.

## Сценарий для демонстрации

1. Зарегистрировать новый аккаунт и на Главной показать начальные рекомендации.
2. В Header найти «Неоновые линии ведут меня домой» или «Ночной импульс». Открыть исполнителя «Пульс города», затем трек и нажать «Слушать».
3. Запустить также «Электрический свет» и «Частота рассвета» в обычном режиме. В `/profile` показать электронный жанр, исполнителя и статистику. Вернуться на Главную: карточки остались на месте. Перезагрузить страницу и показать новые рекомендации.
4. Добавить «Утро у реки» и «Роса» в избранное или сохранить несколько треков в плейлист. Показать изменение весов в профиле; перезагрузить Главную для обновления рекомендаций и раскрыть «Почему?» у трека.
5. Включить гостевой режим и найти «Облако-котёнок». Запустить детский трек, не добавляя его в избранное/плейлист.
6. Показать отдельный гостевой запуск в библиотеке: обычный профиль и рекомендации остались прежними.
7. Выключить гостевой режим и запустить «Тёплый воздух». Показать новый обычный запуск и изменение профиля.
8. Обновить свой плейлист под текущий вкус. Перезагрузить страницу: библиотека и персонализация восстановятся. Выйти и зарегистрировать второго пользователя: он получит свой пустой профиль и начальную подборку.

Каталог содержит 21 вымышленный трек, 7 исполнителей и 5 жанров. Исходные ID треков 1–12 сохранены.

## Проверки

```bash
npm run lint
npx tsc --noEmit
npm run build -- --webpack
node scripts/test-personalization.cjs
node scripts/test-state.cjs
node scripts/test-auth.cjs
```

Автоматические проверки чистых модулей подтверждают изменение персонализации от обычной истории, избранного и плейлистов; неизменность от гостевых событий; уменьшение повторов; валидацию и восстановление данных; ограничения истории; работу очереди и режимов Player.

Открытые маршруты: `/login`, `/register`. Защищены все музыкальные экраны, включая `/`, `/search`, `/library`, `/profile`, `/artist/[id]`, `/track/[id]`, `/playlist/[id]`. Неизвестные треки/исполнители показывают 404; отсутствующий локальный плейлист — понятное пустое состояние.

## Границы демонстрационной версии

- **Аудиофайлов нет: Player честно обозначен «Демо · без звука».** Работает таймер и состояние интерфейса. Для локального аудио можно добавить файл в `public/audio` и указать `audioSrc` у трека в `lib/demo-music.ts`; общий HTML5 Audio уже подключён.
- Тексты песен статические: синхронизация строк с аудио не реализована.
- Каталог, обложки и статистика исполнителей демонстрационные. Обложки выполнены локальными SVG.
- Production-авторизация с серверной проверкой, PostgreSQL, внешний AI, распознавание музыки, офлайн-загрузка, радио и уведомления о релизах не реализованы. Неработающие элементы этих функций не показаны как рабочие кнопки.
- Аккаунты и личные данные относятся к этому браузеру и origin. Каждая история хранит до 500 последних событий, плейлистов может быть до 100. При недоступном localStorage всё продолжает работать в памяти текущего сеанса.
- Для чистой демонстрации зарегистрируй новый локальный аккаунт или используй новый профиль браузера.
